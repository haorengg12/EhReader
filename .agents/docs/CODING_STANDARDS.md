# 编码规范 — V2.2

本文件是代码风格、注释和实现质量的权威来源；执行命令见 [本地开发](LOCAL_DEVELOPMENT.md)，测试范围见 [测试规范](TESTING_STANDARDS.md)。

## 编码与命名

- 文本使用 UTF-8 无 BOM、LF，文件末尾保留换行；保持中文原文。使用现有 .editorconfig、.gitattributes 与 Spotless/ktlint 配置。
- Kotlin 遵循现有项目风格和有语义的英文命名；类名 UpperCamelCase，函数及属性 lowerCamelCase。避免万能类、无依据的抽象和与需求无关的全局格式化。
- 关键函数使用中文 KDoc：说明业务目的、重要约束、参数、返回与失败行为。重点覆盖数据库迁移、文件操作、下载调度、解析、兼容逻辑；简单访问器不强制重复注释。
- 修改行为时同步更新相关注释、说明和必要测试；不为满足篇幅要求堆砌注释或机械测试。

## 实现约束

- 按 [架构规范](ARCHITECTURE.md) 维护边界。现有 Fragment/Scene/XML 功能不强制迁移 Compose。
- 协程遵循结构化并发和生命周期，避免主线程阻塞，不吞掉取消异常。错误须保留排查信息，日志不得包含密码、Cookie、令牌或私钥。
- 文件和数据库修改考虑完整性、失败恢复和旧数据兼容，未经明确批准不执行破坏性迁移。
- 不随意引入或升级依赖；记录必要变更的用途、兼容性和验证结果。detekt 尚未配置时不得声称通过该检查。
- 保留上游版权、许可证和 Git 历史；haorengg12 的版权声明只覆盖新增原创修改。遵守仓库 LICENSE、NOTICE 和第三方声明。

## 数据库文档同步

每次数据库表关系或结构发生改变，必须在同一次修改中同步代码、当前导出 schema 及相关文档，不能只改数据库实现。适用范围包括表的增删改名、字段的类型/可空性/默认值、主键/外键/索引/唯一约束，以及业务关联的实际语义。

- 更新工作区根目录的[数据库表结构与关系一览](../../../EhReader数据库表结构与关系一览.md)，同步表/列清单、约束、索引、关系图、版本与字段含义；不得把计划中的表或关联写成已经实现。
- 同步受影响的需求或功能说明；已有记录和历史 schema 按当时事实保留，不能为更新当前结构而改写旧版迁移依据。
- 核对文档与当前实体、DAO、实际导出 schema 和升级方案一致，执行适用的文档链接/编码及数据库检查。结构改变需要的兼容迁移不能以文档更新替代。

本规则细化既有实现与文档同步要求，不改变开发阶段、提交推送权限或打包/发布条件。
