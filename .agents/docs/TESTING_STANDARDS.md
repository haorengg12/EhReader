# 测试规范 — V2.2

本文件规定覆盖范围与结果解释；本地命令见 [本地开发](LOCAL_DEVELOPMENT.md)，CI 跟踪见 [仓库管理](REPOSITORY_WORKFLOW.md)，正式门禁见 [发布规范](RELEASE_POLICY.md)。

- 新增或修改核心业务逻辑须覆盖正常、边界和失败路径。测试应验证实际行为，避免只重复实现或为纯文档修改增加测试。
- 文件、下载：验证权限失败、空间不足、中断恢复、重复任务、并发、完整性、临时文件和 CBZ 失败恢复。
- 数据库：验证迁移前后记录、关联一致性、失败恢复、重复迁移和旧数据保留；破坏性迁移需明确批准。
- UI/资源变更按影响验证布局、导航和交互；设备或模拟器不可用时明确记录未做运行测试，不能以构建通过替代运行验证。
- 版本与材料顺序按[开发流程](DEVELOPMENT_FLOW.md#版本准备第-2-阶段)，人工测试安排通过[最终审核单](DEVELOPMENT_FLOW.md#最终审核单)表达，权限含义以[仓库管理](REPOSITORY_WORKFLOW.md#状态与授权范围)为准。测试规范只定义真实结果：待安排/待结果/通过/未通过/无需等待分别记录，不沿用旧包通过结论。
- 使用现有 Spotless/ktlint、Android lint 和适用测试。工具尚未配置或任务缺失时报告，不声称通过。
- 本地打包统一在 Docker 中完成，执行[本地开发规范的 Docker 检查与验收](LOCAL_DEVELOPMENT.md#docker-检查与验收)；源码替换后的产物须标明实际输入，容器构建与设备验收分别给出结论。
- NO-SOURCE 表示无测试源；SKIPPED/取消/未运行必须单独报告。历史项目无测试不能被描述为“全部单元测试通过”；本次修改核心业务时应补充有意义的测试。
- 编译失败、检查错误或测试失败阻止成功结论。历史警告须记录数量和范围，不自动全量修复；新增相关警告应解释或处理，不以关闭检查隐藏问题。
- 远端验证分别记录基础质量检查、APK 构建和发行的实际结果，分流规则见[发布规范](RELEASE_POLICY.md#基础验证与打包分离p1-13)。未打包不能写作未运行基础验证；本地结果不替代同 SHA 的远端检查或正式 merge SHA 验收。
- 纯规范任务本地只做文本、链接和内容一致性检查，不在本地编译；推送后按版本位置决定 CI，不因文档任务额外触发构建。目标分流仍待工作流适配，不能把规范检查通过写成已完成部署。

## 检查结果的复用与失效

复用以每项检查的真实输入为单位，不仅比较阶段、Git SHA 或文件时间。记录输入内容 SHA-256、配置、检查器实现、实际工具版本/环境和检查范围，并保留原始成功日志及其散列。未提交内容也属于输入；同一 SHA 下内容改变不能复用，仅 SHA 改变但相关输入未变也不强制重跑。

| 检查 | 本地入口用于判定的输入 |
| --- | --- |
| 文本编码 | 本次范围内文件内容、检查器与调度实现、Node/Git 版本及环境 |
| Markdown | 实际扫描文档、标题锚点所引用 Markdown 的内容、本地目标的存在性、工作区检查范围及上述工具输入 |
| Node 语法 | 本次 JS/MJS 内容及 Node 工具/环境；其他文档变化不使其失效 |
| Node 测试组 | scripts 目录全部输入、发行模板、调度及检查实现、Node/Git 工具与环境；按整个测试组保守失效，不声称已精确推导所有业务调用关系 |
| 差异/空白检查 | 本次文件内容、工作树与暂存区差异、.gitattributes/.editorconfig 和 Git 工具环境；不能漏查暂存内容 |
| Docker Debug | 当前入口的持久调试签名卷、完整实际工具证据等尚未自动固定，不自动复用旧构建；源码/配置/镜像/替换内容仍按本地构建验收留证 |

只有实际成功且当前输入匹配、原日志仍存在且内容未变的检查才标记 `reused`，保留原日志来源；失败、取消、未运行、NO-SOURCE 或无法证明输入完整的结果不能作为复用成功。检查过程中输入变化时该结果失效。符号链接或外部 Node 注入模块等未固定输入不自动复用；环境只存散列，不将凭据原文写入记录。调度器覆盖的临时目录、沙箱临时 LOCALAPPDATA 和工具调用编号不作为项目输入；若检查实际依赖这些目录里的内容，须增加真实依赖或重跑，不能套用当前缓存范围。

继续本地任务时逐项判断，只重跑失效或失败的检查；未受影响的成功检查继续复用。`status` 会重新核对当前有效性，`stale` 表示存在已失效结果，不能把旧 state.json 中的成功状态直接当作当前验收。手工检查复用也须符合这些条件，超出自动输入覆盖范围时补查或重跑，不静默套用缓存。

检查结果有效不等于人工测试通过或取得推送许可；实质变更仍按最终审核单重新核对受影响的验收/权限。develop CI 与正式 merge SHA 构建均独立记录；合并后的正式构建、签名及发行检查不复用本地 Debug 或其他 SHA 的结果。本条不改变版本分流和远端工作流。
