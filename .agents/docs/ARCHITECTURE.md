# 架构规范 — V2.1

- 当前 EhReader 保留既有 Fragment/Scene/XML 和原生库结构。维护已有功能时遵循现有边界，不强制迁移 Compose。
- 新模块或用户批准的迁移可采用 MVVM + Repository；复杂且复用的业务按需引入 UseCase。Compose 是可选演进方向，采用前确认与现有页面、生命周期和导航兼容。
- 新增 UI 逻辑通过清晰接口使用业务/数据层，避免直接嵌入数据库或解析逻辑。旧代码渐进治理，不为一次修复进行全局重构。
- 文件系统与下载集中管理，考虑权限、完整性、中断恢复及失败清理；使用稳定作品标识维护关联。
- 数据库变更提供迁移及验证方案；旧数据处理先识别、迁移、验证和恢复设计，再考虑下线旧逻辑。破坏性迁移须单独获准。
- 具体代码要求见 [编码规范](CODING_STANDARDS.md)，测试范围见 [测试规范](TESTING_STANDARDS.md)。
