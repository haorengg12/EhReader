## 2026-11-11 下载完成 CBZ 打开失败修复

用户日志中四次崩溃均发生在通过 /proc/self/fd 重开已授权 CBZ 的读取阶段，系统返回 EACCES。完成归档改为直接使用已授权 URI 的输入流逐条定位目标页，不依赖文件描述符路径重开、可写归档或可寻址的 provider 流；保留页名/页序、CRC 和主库 SHA-256 校验。图片仍按需写入下载根的 temp_read/GID，缓存命中不重读归档，不修改 CBZ 和原成品目录。流式查找首次读取靠后的页需要扫描前面的条目，避免额外复制整份归档或引入新的归档副本。

解码任务在取得图片源失败时记录原因并通知页面“读取失败”，不让文件 I/O 异常成为未捕获协程崩溃；协程取消仍向上传播。数据库、元数据留白显示及下载完成记录不变。本次不升版、不打包、不创建 Tag，代码检查后提交本地 develop；设备上的 Android/SAF 实际回归留待后续测试。

## 2026-11-11 恢复下载项与清理下载冗余

本节为最新指示，取代此前只重新关联已登记位置、不扫描可识别成品的限制。下载设置标题恢复为“恢复下载项”，两项操作均只作用于当前授权下载根的新版 分类/GID 布局；只在手动点击时扫描，不在启动或换目录时自动扫描。根目录旧式 GID-标题 目录和 .ehviewer 文件继续留给兼容性功能，不在本轮迁移。

- 新版每个画廊目录补充 .ehreader 续传身份文件，正常下载准备、完成及关闭时保存，恢复时补齐。该文件沿用 SpiderInfo 的 CBOR（也保留旧编码解析能力），含 GID、token、页数、页面 token/预览/阅读位置快照及可选的下载格式；不保存完整画廊元数据，不是数据库，应用主库仍为权威来源。写入先完成 part，再保留 bak 并发布，失败保留旧副本或可重试的完整临时文件。
- 恢复依据 .ehreader、ComicInfo.xml 中的画廊 URL 或主库现有身份识别画廊；缺少记录可重新建立元数据占位、下载和位置关系。标题缺失且 token 可用时尝试在线补齐，联网失败不阻止利用本地身份恢复。主库丢失且本地没有身份信息时不承诺完整离线重建，无法识别的目录跳过。
- CBZ 校验归档条目、CRC、完整中央目录和页序/页数；散图校验编号、图片可读性和散列。完整内容才标记完成；已识别的临时目录恢复为暂停状态，保留原定格式，不自动开始下载。发布中断且原清单与暂存文件一致时保留发布状态供续传重试。恢复不搬动或覆盖图片，不将不完整下载伪装为完整成品。
- 同 GID 多个目录、身份/token/页数冲突、损坏归档、混合成品格式等逐项报告失败；其他根已有有效且内容不同的位置不直接覆盖。库内以事务重建关系，保留已有下载分组、时间、旧路径、旧库导入标记及阅读进度；新下载记录使用默认 false 的旧库导入标记。历史、收藏、书签不被清空。
- 清理除了检查已登记位置，也识别尚未登记的新版遗留成品。只有精确登记的位置、本地有效身份文件或没有未知附属项的纯有效成品，才能作为删除依据；仅在主库有同 GID 元数据不足以删除未知文件。整个目标 GID 文件夹和对应阅读缓存一并清理，分类父目录、其他 GID、temp_read 根及其他下载根保留。已在下载列表中的 GID 和正在阅读的画廊跳过。
- 恢复/清理共用互斥任务；有活动下载先停止，过程中复核下载活动和根目录变化，并在单画廊操作前复核占用。列举、校验、写身份文件、事务和删除失败都保留实际结果；删除失败不移除位置，实际删除后只清除与本次根/路径吻合的位置记录。结果分别统计恢复/清理、跳过和失败，不把失败或不可访问当成没有冗余。

数据库表、字段、外键及 schema 2 均不改变；现有 READING_STATE.SPIDER_INFO 的可选编码字段兼容旧值。结构总览同步说明续传侧文件与恢复事务。本轮不升版、不创建 Tag；用户后续要求打包，沿用 1.8.15.1 / 10816 生成 ARM64 Debug，完成必要检查后按约定提交本地 develop。

## 2026-11-10 下载画廊详情的本地回退

从下载列表点击缩略图仍进入原详情页并沿用在线请求。超时、网络失败、画廊下架、HTTP 404 等异常时，按当前 GID 读取主库 `GALLERY_METADATA`，完整和部分元数据均可展示；没有主记录且也没有已加载详情时，保留原错误页。

回退后继续展示已有标题、封面、上传者、分类、语言、页数、大小、发布时间、评分及 Tag；缺失元数据留空，不填充“未保存”或其他占位文字，不将未知人数/页数伪装为 0，也不将未知评分作为有效分数；已有数值 0 正常显示。评分已知、人数未知时只显示分数，不追加人数未保存说明。未保存的评论和预览区不展示。完整信息列表同步留空，缺少分类或当前账号收藏快照时也不填充默认分类/false；其余页面原有操作文字和异常 Toast 保留。封面沿用本地下载封面优先的加载路径。

回退时用系统 Toast 显示“正在显示本地保存的画廊信息”及原错误说明，保留 HTTP 状态码和站点返回的不可用原因；提示数秒后自动消失，不带按钮，不新增刷新入口。手动刷新继续使用详情页右上角原有菜单，直接重新请求在线详情。已下载画廊刷新成功时，同样按 GID 合并并保存主库元数据（含来源、账号快照及更新时间），下载列表通过元数据变更通知同步；刷新期间已有内容继续可读，成功后恢复在线详情；重复刷新合并到在途请求。每次失败只提示一次，返回页面或旋转不重复已显示的 Toast，尚未显示的提示可在恢复后显示；离开页面取消当前 Toast。本地回退不作为在线成功写库，不覆盖有效元数据或更新时间，也不改动下载位置和阅读进度。

本次不改变数据库表、字段、关系或 schema 版本；结构仍为主库 schema 2。本地回退、在线刷新及生命周期显示需在后续设备验收中核对，不用代码编译结果代替实际界面验收。

## 最高优先级：不导入旧数据的新逻辑闭环

本轮用户明确要求先完成数据库结构和下载目录重构。**第一阶段必须在没有旧数据库、没有旧文件、从未执行旧数据导入或路径重建的条件下，按新逻辑正常使用。** 此要求是最高优先级及阶段验收条件，取代此前将部分正常下载、刷新、清理或阅读适配放到旧数据导入之后的顺序。

| 阶段 | 范围与进入下一阶段条件 |
| --- | --- |
| 第一阶段：最高优先级，F09 + F10 与必需依赖 | 新主库及 GID 关联、新元数据写入/查询、分类/GID 下载目录、CBZ/散图、任务恢复与阅读等正常业务适配。独立验收新数据闭环通过后，才推进第二阶段。 |
| 第二阶段：旧数据接入，F11 | 实现“导入旧版本App数据”和“重建下载路径”，复用已验证的新主库、下载布局和读写能力。不得反过来要求新用户先导入或先重建才能使用。 |
| 后续增强 | 全库批量刷新与新增作者、Tag、搜索等能力按后续排期推进；已有业务的基础适配和正常获取/保存元数据不能以“增强功能”为由延后。 |

新下载直接创建元数据及下载业务记录，直接生成新版目标和实际位置；`LEGACY_DOWNLOAD_PATH` 为空是正常情况，不能作为启动、下载、续传、阅读或删除的必填项。新版核心不依赖旧 schema、旧目录映射、旧 `.ehviewer` 文件或导入器生成的数据。

### 第一阶段完成条件

1. 全新安装或空数据环境直接初始化新主库；未导入时能浏览详情、创建新元数据，以及正常读写下载、历史、收藏等现有功能记录。列表展示与查询均使用新结构，不保留公共字段副本。
2. 自选/默认下载根可直接下载，CBZ 默认开启，关闭可下载散图；分类/GID 目录、六位随机片段临时目录、实际位置及完成状态由新流程独立维护，下载目录不生成 DB。
3. 下载暂停、进程退出后恢复、失败重试、封面、离线阅读和阅读进度在新布局下可用；重启后仍使用新主库记录，不依赖旧路径回退或手动重建。
4. 仅移除记录、删除文件、冗余清理及现有升级画廊入口适配新位置，保护其他内容与历史/收藏关系；元数据正常获取/更新和新版现有备份/还原能力完成受影响适配。全库批量刷新可后置，但不影响这些基础行为。
5. 普通文件与 SAF 目录分别验证正常路径及空间不足、权限丢失、归档中断、文件已写但主库未提交等异常；未知分类进入 `unknown`，重复任务不争写。
6. 更新安装而跳过旧数据导入时，新库仍能使用并新增数据；保全旧库及必要 WAL 数据是最低数据保护，不等于自动迁移，也不要求先完成第二阶段导入器或旧进度解析。

上述为待实现、待执行的验收条件，不代表当前应用已通过。第一阶段的基础 schema、事务、索引、删除及位置策略需要先落实；旧字段冲突合并、旧格式转换和旧续传兼容细则不作为第一阶段前置依赖。

## 本轮决策与范围

本轮用户指示取代 V0.8–V0.9 中冲突的方案：

1. 重构原 `eh.db` 的存储结构。画廊公共字段集中存入 `GALLERY_METADATA`，关联业务表只保存 GID 和各自业务字段，不再复制元数据。
2. 删除“设置 → 兼容性”页面需求，在“设置 → 高级设置”增加“导入旧版本App数据”。
3. 删除启动后及更换下载目录后的旧格式兼容性检查与迁移弹窗。旧格式识别仅在手动导入时执行。
4. 下载根目录不再生成数据库。本文按同时取消根目录数据库和各画廊目录下的 `<GID>.db` 理解，元数据集中保存在应用私有主库；若用户仅指根目录单一 DB，需再调整此边界。

| 本轮补充答复 | 当前处理 |
| --- | --- |
| 旧数据导入 | 只导入数据库记录，下载记录增加旧下载路径并写入导入的位置，同时按 GID 和分类生成新版目标路径；实际内容整理由独立手动操作“重建下载路径”完成。 |
| 重建下载路径（V0.11 新增） | 设置中增加此功能，建议与旧数据导入同放高级设置；在导入后将已登记下载内容整理到新版分类/GID 结构，校验成功再更新实际位置。 |
| 全库元数据刷新、CBZ 设置 | 保留并移到合适页面；本文建议高级设置提供“元数据刷新”，下载设置提供“保存为CBZ压缩包”，默认开启。页面位置为实现建议。 |
| 目录读取开关 | 删除，新版按实际下载记录和位置读取，不以人工切换读取模式为前置条件。 |
| 更换目录后的旧格式检查 | 与启动检查一起取消；正常的目录权限及位置关联检查保留。 |

## 新数据库与 GID 关联

当前应用主库是 Room 的 `eh.db`，schema 版本 4，包含 8 张表；`DOWNLOADS`、`HISTORY`、`LOCAL_FAVORITES` 和未启用的 `BOOKMARKS` 均继承 `BaseGalleryInfo`，每表保存相同的 10 个字段。这里描述的是现状，不是新结构约束。[主库定义](../../app/src/main/java/com/hippo/ehviewer/dao/EhDatabase.kt) · [公共字段定义](../../app/src/main/java/com/hippo/ehviewer/client/data/BaseGalleryInfo.kt)

新版以 `GALLERY_METADATA.GID` 为画廊唯一主键。`TOKEN`、`TITLE`、`TITLE_JPN`、`THUMB`、`CATEGORY`、`POSTED`、`UPLOADER`、`RATING`、`SIMPLE_LANGUAGE` 统一迁入该表；GID 在其他表中仅作为关联键。最低覆盖“画廊信息”页的 21 项展示信息，并保存此前要求的来源、详情链接和作者/Tag 信息。字段设计与旧数据分析分别见[元数据设计](../../../../Eh项目理解_由Trae国际版生成/元数据数据库.md)和[原版数据库分析](../../../../Eh项目理解_由Trae国际版生成/EhViewer数据库及导入导出分析.md)。这两份资料在仓库外，独立克隆时需另行提供。

| 逻辑表或职责 | 新结构要求 |
| --- | --- |
| `GALLERY_METADATA` | 每 GID 一条主记录，集中保存公共字段和在线详情元数据。来源、token 是访问属性，不加入画廊主键。 |
| `DOWNLOADS` | GID + 下载状态、时间、分组等下载业务字段；增加旧下载路径（建议名 `LEGACY_DOWNLOAD_PATH`），接收导入的原位置；同时记录按新版规则生成的目标路径。进度字段须明确语义，不再用字段复用掩盖含义。 |
| 下载位置职责（旧 `DOWNLOAD_DIRNAME` 的替代职责） | 保存旧路径、新目标路径、根标识、实际可读位置、格式和临时任务路径等本地字段；不保存标题、分类或详情链接副本。不再只保存最后一级目录名。新目标不是已存在文件；具体位置字段如何分表及多根目录同 GID 的副本规则待设计，旧下载路径字段按用户要求位于下载记录。 |
| `HISTORY` / 阅读状态 | GID + 浏览时间、预览/阅读状态、页码等业务字段。旧 `MODE = favoriteSlot + 2` 必须解码到语义明确的字段，不能继续作为阅读模式使用。 |
| `LOCAL_FAVORITES` | GID + 本地收藏时间和分组等本地状态，与账号在线收藏状态分开。 |
| `BOOKMARKS` | 旧版仅声明、未启用且不参与常规导出；如新版保留，仅保存 GID + 页码、时间等书签字段。原始库中有数据时须保留或明确报告，不静默丢弃。 |
| 作者、Tag、手动分组的作品关联表 | 以 GID 关联作品，另外保存作者/Tag/分组自身 ID，不得再次复制公共画廊字段。 |
| 下载标签、快速搜索、过滤规则 | 并非每行都代表一部画廊，不强行增加 GID。搜索条件中的分类、标签名称等属于业务条件，不等同于画廊元数据副本。 |

“仅用 GID 关联”针对画廊身份，不要求所有表只有 GID 一列，也不禁止关联表引用其他业务实体。需要新增 GID 的关联表必须补齐；已有 GID 的表直接复用。

物理库名、schema 版本及升级实现待设计，不再受旧表形态约束。禁止为重构而直接清空原库；更新安装时先保全旧主库及必要的 WAL 数据，再初始化新库，不能因启动读取不兼容 schema 而破坏导入来源。保全旧数据不属于下载目录兼容性扫描，也不得自动导入旧记录。

### 一致性与缺失数据

- 先建立元数据主记录，再写业务关联，使用事务维护数据库内一致性；外键、索引及删除策略在实现设计中落实，不沿用“旧库无外键，所以新库也不加”的推论。
- 缺少 token、标题或在线详情的旧记录可建立仅含已知字段的占位记录，标明待补全；不把未知评分、页数或收藏状态伪装成有效零值。
- 删除下载记录只影响相应业务记录；仍被历史、收藏等业务引用的元数据不能级联删除。文件删除按用户选择执行。
- 同一 GID 的旧元数据可能在四表中互相矛盾。先保留来源与冲突，空值不覆盖有效值；不能用浏览时间推断哪份在线元数据更新。合并优先级待设计。
- 来源和完整详情链接存于元数据主记录；业务列表通过 GID 查询获得。只有 GID 或站点不明确时保留待补全状态，不拼出看似有效的链接。
- 在线刷新保护本地 Tag、作者关注、历史、进度和位置；在线收藏/评分属于账号相关快照，应与本地收藏区分，账号切换不能直接沿用为当前状态。

## 下载布局与完成条件

下载根目录沿用应用设置，以分类 `doujinshi`、GID `4301918` 为例：

| 用途 | 路径示例 |
| --- | --- |
| 下载完成，CBZ 为既有默认要求 | `~/download/doujinshi/4301918/4301918.cbz` |
| 下载完成，散图 | `~/download/doujinshi/4301918/00000001.jpg`、`00000002.jpg` 等，扩展名随图片格式 |
| 下载中，两种模式共用 | `~/download/doujinshi/4301918/4301918_a3f790_tmp/`，随机片段为六位小写十六进制字符 |
| 在线元数据及业务记录 | 应用私有主库；下载根及各 GID 目录不创建 `.db` 文件 |

临时名称冲突时重新生成，实际路径记录在任务中；暂停和重启沿用该任务路径。同一 GID 的重复请求应复用或协调已有任务，避免争写成品。页数、顺序和可读性校验通过后写出选定格式，再提交主库中的下载状态和位置；成功后清理本次临时文件。数据库与文件无法整体原子提交，须有可恢复状态和补偿机制。半成品不能出现在已完成列表。

元数据主表与位置记录组合后，至少能查询完整详情链接、相对于所选根目录的内容路径和格式。CBZ 记录 `doujinshi/4301918/4301918.cbz`，散图记录 `doujinshi/4301918/`。导入旧记录时先生成新版目标目录 `分类/GID/`，未知分类用 `unknown/GID/`；这只是路径规划，实际建目录和写文件由后续下载或文件整理执行。SAF 根目录保存授权 URI/根标识，逐级创建分类和 GID 目录，不把文件路径当作通用 URI。

网站分类使用固定小写目录名：`doujinshi`、`manga`、`artistcg`、`gamecg`、`imageset`、`cosplay`、`asianporn`、`non-h`、`western`、`misc`、`private`、`unknown`。未知分类进入 `unknown/<GID>`。标题、作者和用户下载标签不参与路径；后续分类刷新不自动搬文件。[分类映射](../../app/src/main/java/com/hippo/ehviewer/client/EhUtils.kt) · [现有命名](../../app/src/main/java/com/hippo/ehviewer/spider/SpiderDen.kt)

取消随库 DB 后，仅凭 GID 目录名无法离线重建 token、来源、标题、Tag、历史及阅读进度。新版备份必须包含主库元数据和业务关系；恢复后由用户重新授权根目录并核对实际文件。是否写入 `ComicInfo.xml` 或 CBZ 内交换元数据仍待确认，不能当作已确定的替代 DB 方案。主库丢失而只剩图片/CBZ 时，最多登记能核实的身份和位置，其余标为待补全。

## 设置 → 高级设置 → 导入旧版本App数据

本功能安排在第二阶段，新逻辑闭环先独立完成并验收；跳过导入不妨碍第一阶段正常使用。

这是手动入口。用户选择旧版导出的数据库，识别支持的 schema、预览数据与冲突后启动导入；不把旧库直接当新版主库打开，不静默替换全部当前数据。

旧版已有“导出数据”和“导入数据”，导出实际复制 7 张表；图片、`.ehviewer` 阅读进度、Cookie、搜索建议、设置和标签翻译不在该导出中。普通导出也不包含 `BOOKMARKS`。新版备份还原与旧版导入须明确格式及错误提示，旧版转换逻辑由独立适配层负责。[现有导入导出](../../app/src/main/java/com/hippo/ehviewer/EhDB.kt) · [高级设置](../../app/src/main/res/xml/advanced_settings.xml)

| 来源数据 | 导入目标与限制 |
| --- | --- |
| 旧画廊表中的公共字段 | 按 GID 归并到 `GALLERY_METADATA`，再建立下载、历史、收藏等业务行；保留来源与冲突，不复制四份元数据。 |
| 下载标签、快速搜索、过滤规则 | 保留业务语义，按新版实体 ID/去重规则转换，重新映射关联。 |
| 旧目录映射 | 将原下载位置写入下载记录的旧下载路径，再生成新版目标路径。旧 `DIRNAME` 只是目录名，需结合授权旧根才能定位；未知根时保留原值并标为待关联，不能声称已找回图片或完成迁移。 |
| 缺少元数据、无效 GID、未知 schema、损坏数据库 | 分别报告待补全、拒绝/隔离原因与可重试项目，不静默忽略单表异常并报告全部成功。 |
| 旧下载目录及 `.ehviewer` / `ComicInfo.xml` | 导入不整理、转换或删除文件；“重建下载路径”单独处理实体内容，也不从旧导出库臆造文件进度。 |

重复导入应幂等，保留已有用户数据；有冲突时显示处理结果或待决定项。导入支持中断后重试，以画廊及其业务关系为一致性单位，另外处理独立规则表。数据库转换、旧路径保存、新目标路径生成和实际文件存在性分别报告，不显示文件迁移成功。

旧状态可留作来源信息，但等待/正在下载的记录须归一为暂停或待处理，不能按导入前状态自动加入运行队列。旧记录标记下载完成也不等于本机文件存在或可读；缺文件、权限或完整性证据时单独标明待关联/待核实，列表不能误报本地内容可用。

旧位置、新版目标和实际可读位置必须区分。生成目标路径不应切换当前读取位置；对已授权且存在的旧位置可记录实际定位结果，缺权限/文件时标为待关联。导入不自动恢复未完成下载；旧任务续传适配留待设计，重建期间受影响任务须暂停并协调访问。

实体文件整理已由下方独立功能承接，不混入数据库导入验收；导入成功不代表重建成功。

## 设置 → 高级设置 → 重建下载路径

本功能与旧数据导入同属第二阶段，不作为新下载或新用户开始使用的步骤。

功能名称固定为“重建下载路径”，放在设置中；本文建议与“导入旧版本App数据”同置高级设置。用户导入旧数据后手动执行，以下载记录中的旧路径、实际位置和新版目标路径为依据，把真实内容整理为 `分类/GID/` 结构。它不只是重新计算数据库路径，也不由导入完成、启动或更换目录自动触发。

例如旧目录 `~/download/4301918-标题/` 中的有效图片，重建后进入 `~/download/doujinshi/4301918/`；CBZ 成品名称为 `4301918.cbz`，散图按 `00000001.jpg` 等页序编号，保留实际扩展名。缺分类时使用 `unknown/4301918/`，缺 GID 或无法核实来源时跳过并报告，不靠相似目录名猜测身份。

### 操作范围与流程

1. 读取已登记下载记录，要求来源和目标根目录具备访问权限，展示待处理数量、旧/新位置、冲突、缺失文件及空间需求。未登记文件和无关目录不纳入批量处理；核对来源文件属于本记录，不重新启动全目录旧格式兼容扫描。
2. 对本次清单固定 GID、分类、目标位置及开始时 CBZ 开关决定的目标格式。执行中开关或在线分类变化不改变本次目标，来源或根目录发生实质变化时停止该项并重新核对。路径与目标格式均符合要求且校验通过的条目跳过；已授权的旧位置为来源，缺权限或文件时显示待处理。
3. 暂停受影响的下载，协调阅读与清理，逐画廊在可恢复的临时位置整理内容。记录页序、源目标对应、状态和错误，保留封面及有效本地进度/续传信息，不盲目重命名附属文件。部分下载不得误标为完整成品。
4. 校验图片/归档可读性、页数和顺序、身份及进度映射后，提交实际相对路径和格式。GID 不变，历史、收藏、作者/Tag 及阅读状态关系保留；旧下载路径作为来源留痕，不因成功而立即清空。
5. 原文件至少保留至目标校验和主库位置提交成功。旧副本清理作为明确的用户选项，限定在本次已确认的来源，保护其他画廊、父目录和未知文件；不同时清空整个下载根。
6. 显示成功、跳过、待关联、冲突和失败数量及原因，可中断后继续或单独重试。按单画廊恢复，目标已写而主库未提交时须核实后接续，不重复搬运或产生多份成品。

已确认按“保存为CBZ压缩包”开关转换：开启时将完整散图打包为 `<GID>.cbz`，已有有效 CBZ 可校验后复用；关闭时保留或从 CBZ 提取编号散图。即使目录已符合新布局，格式不符合本次选择仍需转换。转换须保持页序、实际图片格式及阅读进度，目标格式在开始时固定，中断恢复沿用该选择。图片未下完或完整性无法确认时保留为未完成/待核实条目，不伪装成完整 CBZ 或已完成下载。

同 GID 目标已存在时不得直接覆盖：核对身份、实际格式和完整性；相同且有效可复用，不同内容或多个来源则报告冲突。来源与目标相同、嵌套或互相包含时须识别，避免把目标重新当来源或递归复制。空间不足、授权失效、取消或进程退出时，保留可用原件和有效位置，不误报完成。下载根和画廊目录仍不生成数据库，恢复记录存应用主库。

同目录内转换格式时，源清单与目标清单须分别固定，旧副本清理只针对已验证且可删除的旧格式文件，不能删除已经写入的新内容或整个目标目录。归档提取应核对条目名称、输出边界、页序和重名，遇异常归档保留原件并报告；无法映射已有有效阅读/续传信息时列为待处理，不静默丢失进度。重建无需强制联网，分类缺失可使用 `unknown`，远程元数据刷新仍为独立操作。

## 元数据获取与刷新

下载时获取在线元数据；单画廊可手动刷新；点击没有主记录的画廊时，按可用来源、GID、token 请求并入库。重复点击、刷新及下载须合并并发写入，业务表无需同步复制标题等字段。

全库刷新已确认保留并调整页面，建议放在“高级设置 → 元数据刷新”；下载格式开关建议放在“下载设置 → 保存为CBZ压缩包”，默认开启，关闭后保存散图。目录读取开关删除。刷新更新 `GALLERY_METADATA` 和作者/Tag 索引；离线、下架、权限不足或部分响应失败时保留有效前值及本地可读内容。无来源或 token 的条目可待补全，不将失败写成完整元数据。刷新不生成下载目录 DB，也不隐式重写 CBZ 或搬动文件。

## 建议实施顺序

1. **第一阶段：数据库重构。** 固定新主库字段归属、GID 关系、缺失值语义、事务/索引/删除策略，打通新数据的元数据、历史、收藏、下载与查询。旧路径允许为空，保全旧库不依赖导入器。
2. **第一阶段：下载目录重构。** 打通分类/GID、临时目录、CBZ/散图、新任务持久化、暂停恢复、阅读、封面和进度，并适配正常删除、清理、升级、元数据更新及现有新版备份还原。
3. **第一阶段独立验收。** 按上方完成条件，在完全无旧数据且不执行导入/重建时验证新逻辑闭环，并验证升级跳过导入仍可新增和使用数据；通过后才进入第二阶段。
4. **第二阶段：旧数据库导入。** 实现旧 schema 识别与归并、旧路径写入、新目标生成、冲突和中断恢复，导入不整理文件，不覆盖第一阶段已产生的新数据。
5. **第二阶段：重建下载路径。** 接入旧文件与旧进度适配，复用第一阶段内容读写和格式能力，验证实体整理、校验、位置提交、来源保全及恢复。
6. **后续增强。** 完善全库批量刷新和新增作者、Tag、搜索功能，再评估旧业务下线；具体版本另定，不延后第一阶段必需的现有业务适配。

## 建议验收场景

先单独执行“第一阶段完成条件”。下列涉及旧数据导入、字段合并及重建的场景归第二阶段，不能以这些场景尚未实现为由阻塞新用户闭环，也不能用导入后的运行结果替代无旧数据验收。

1. 同一 GID 同时出现在下载、历史、收藏和书签关系中：元数据仅一份；修改标题后各列表一致，关系表无标题/token 等副本，无孤立关系。
2. 合并旧表中同 GID 的冲突值，检查空值、缺 token、非法 GID、收藏槽位编码及未启用书签，区分成功、待补全、冲突和失败。
3. 仅导入旧导出库时，7 张表可用数据保全，明确未含图片与阅读进度。未知 schema、单表失败、中断及重复导入不误报全成功、不清空新数据。
4. 更新安装、全新安装和跳过导入均能使用新库；启动及换目录均不进行旧格式扫描和迁移弹窗，只有手动导入识别旧格式；目录读取开关不存在。
5. 在普通文件和 SAF 根分别验证 CBZ、散图、标题特殊字符、未知分类、暂停重启及离线阅读；根目录和各 GID 目录不产生 `.db`。
6. 模拟随机目录重名、空间不足、权限失效、归档中断、成品已写但主库未提交，重试沿用任务，只出现一份有效成品。
7. 导入带旧目录映射的数据库，旧位置写入下载记录，按分类/GID 生成新目标，未知分类进入 `unknown`。目标尚无文件时不得误切换位置；重复导入不覆盖已核实有效位置，不创建第二份成品，不搬迁或删除旧文件。
8. 删除下载记录、删除文件、清理冗余、升级失败时只处理目标范围；历史和收藏引用仍有效。
9. 全量/单项刷新覆盖成功、下架、离线、身份冲突和账号变化；失败保留前值，刷新不修改本地分组、进度或位置。
10. 备份恢复到新根并重新授权，核对元数据与业务关联。仅剩 CBZ/散图而主库丢失时，不承诺完整离线重建；缺失信息必须可见。
11. 导入旧记录后，只有手动点击“重建下载路径”才整理文件。分别在普通文件和 SAF 根验证旧路径到分类/GID 的实体内容、页序、封面、实际格式与阅读进度，成功后离线打开目标，旧来源留痕。
12. 重建遇到已完成目标、同 GID 内容冲突、重复来源、源目标相同或嵌套、未知文件及部分下载时，不盲目覆盖、不递归复制、不误报完整；未登记文件保持原样。
13. 重建时中断、撤权、空间不足，或目标已写但主库未提交后重启，原件与可用位置仍有效，继续/重试只生成一份有效成品；下载/阅读并发不得争写。
14. 重建清理仅处理用户选择的已校验旧副本；已符合布局的记录重复执行可跳过。重建不刷新远程元数据、不修改 GID 或恢复目录读取开关，不生成下载目录 DB。
