# 测试规范 — V2.1

本文件规定覆盖范围与结果解释；本地命令见 [本地开发](LOCAL_DEVELOPMENT.md)，CI 跟踪见 [仓库管理](REPOSITORY_WORKFLOW.md)，正式门禁见 [发布规范](RELEASE_POLICY.md)。

- 新增或修改核心业务逻辑须覆盖正常、边界和失败路径。测试应验证实际行为，避免只重复实现或为纯文档修改增加测试。
- 文件、下载：验证权限失败、空间不足、中断恢复、重复任务、并发、完整性、临时文件和 CBZ 失败恢复。
- 数据库：验证迁移前后记录、关联一致性、失败恢复、重复迁移和旧数据保留；破坏性迁移需明确批准。
- UI/资源变更按影响验证布局、导航和交互；设备或模拟器不可用时明确记录未做运行测试，不能以构建通过替代运行验证。
- 使用现有 Spotless/ktlint、Android lint 和适用测试。工具尚未配置或任务缺失时报告，不声称通过。
- NO-SOURCE 表示无测试源；SKIPPED/取消/未运行必须单独报告。历史项目无测试不能被描述为“全部单元测试通过”；本次修改核心业务时应补充有意义的测试。
- 编译失败、检查错误或测试失败阻止成功结论。历史警告须记录数量和范围，不自动全量修复；新增相关警告应解释或处理，不以关闭检查隐藏问题。
- CI 必须对目标 SHA 给出独立结果。本地结果作为证据保留，不替代 develop CI 和 master 正式验证。
- 纯规范任务本地只做文本、链接和内容一致性检查，不在本地编译；推送 develop 仍执行统一 CI 打包。
